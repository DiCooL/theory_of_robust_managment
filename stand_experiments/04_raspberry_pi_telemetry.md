# Телеметрия через Raspberry Pi по Wi-Fi

Схема: плата Миландр → USB (X1) → Raspberry Pi Zero 2 W → Wi-Fi → ноутбук. Pi читает кадры телеметрии и пишет полный лог на свою карту; ноутбук видит строки состояния через SSH и забирает файл по `scp`.

## Подключение

1. Кабель от разъёма X1 платы вставить в разъём `USB` на Pi (не `PWR IN`; нужен кабель с передачей данных). Питание Pi подать отдельно в `PWR IN` (зарядка 5 В).
2. Pi и ноутбук должны быть в одной Wi-Fi сети (Pi Zero 2 W работает только на 2.4 ГГц).
3. Имя Pi `pidron`, пользователь `user`. Вход с ноутбука (cmd):

```
ssh user@pidron.local
```

Если имя не находится, найти адрес Pi: `ipconfig` (подсеть ноутбука), обход подсети `for /L %i in (1,1,254) do @ping -n 1 -w 150 192.168.X.%i | find "TTL="`, затем `arp -a` и поиск устройства с физическим адресом Raspberry Pi (начало `2c-cf-67`, `d8-3a-dd`, `dc-a6-32`, `e4-5f-01`, `88-a2-9e`, `b8-27-eb`; при случайных MAC-адресах признаков может не быть) и вход по адресу: `ssh user@АДРЕС`. Устройство в списке также можно найти в панели роутера.

Адрес `ИМЯ@pidron.192.168...` писать нельзя: имя и адрес указываются раздельно.

## Проверка, что Pi видит плату

На Pi (после входа по SSH), платa Миландр включена и отработала 20 секунд калибровки:

```
lsusb
ls /dev/ttyUSB*
stty -F /dev/ttyUSB0 921600 raw
timeout 5 head -c 66 /dev/ttyUSB0 | od -An -tx1
```

В `lsusb` должна быть строка `Silicon Labs CP210x UART Bridge`, `/dev/ttyUSB0` должен существовать, первые два байта кадра `42 40`. Программы `xxd` на Pi нет, поэтому используется `od`.

Если в `lsusb` нет CP210x, кабель от X1 вставлен не в тот разъём или он зарядный.

## Первый раз: установка

С ноутбука (второе окно cmd, оставить окно SSH открытым):

```
scp D:\download\copter\uav_stand_kit\tools\stand_logger.py user@pidron.local:~/
```

На Pi:

```
sudo apt install -y python3-serial
python3 -c "import serial; print(serial.VERSION)"
```

## Запись лога

На Pi:

```
python3 ~/stand_logger.py --port /dev/ttyUSB0 --duration 50 --every 1
```

Запустить пульт, поднять канал 5, как при записи по кабелю. Файл создаётся в `~/logs/stand_ГГГГММДД_ЧЧММСС.csv` на Pi. Часы Pi не синхронизированы, поэтому время в имени файла сдвинуто относительно ноутбука.

Забрать файлы на ноутбук (cmd ноутбука, не Pi):

```
scp user@pidron.local:~/logs/*.csv D:\download\copter\uav_stand_kit\tools\logs\
python D:\download\copter\uav_stand_kit\tools\check_response.py
```

Результат пробной записи (23.11): 41456 кадров за 50 секунд, плохих кадров 0, пропусков больше 5 мс нет, около 820 Гц.

## Ограничения и что осталось

- Пока идёт запись, SSH-сессия должна быть открыта: при обрыве запись останавливается (уже записанное сохраняется). Нужно запускать в `tmux` или через `nohup`.
- Время Pi не синхронизировано.
- Способ питания Pi на раме не зафиксирован. Сбои сети 23.11 Леонид связывает с питанием (аккумулятор не заряжен до 16 В); вопрос отложен.
- Переход на сеть с телефона: сеть надо записать в настройки Pi (на карте стоит Debian на ядре 6.18; способ записи для этой версии не проверялся).
- Просмотр потока в реальном времени без SSH-окна пока не сделан.
